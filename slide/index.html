Core Claim

복구 대상은 private key가 아니라 owner state입니다

기존 Crypto Wallet

  • EOA 기반 계정
  • seed phrase / private key 복원
  • 복구 시 원본 secret 재노출 가능
  • 복구 후 같은 secret 재사용 위험
→

ERC-4337 Smart Wallet

  • Contract Account
  • wallet owner 상태 교체
  • 기존 private key를 직접 복원하지 않음
  • newOwner로 권한 이전

따라서 본 연구의 핵심은 secret reconstruction이 아니라 owner key rotation을 위한 recovery authorization입니다.

Week 1

기존 복구 방식의 한계

Mnemonic

BIP-39류 백업은 사용성이 좋지만 seed 자체 보존이 핵심입니다.

SSS

k-of-n 복구에는 적합하지만 기본형은 share 검증 기능이 약합니다.

Social Recovery

guardian threshold는 자연스럽지만 replay와 guardian 담합 문제가 남습니다.

PQC Recovery

대부분 일반 지갑의 key material 복구 관점에 가깝습니다.

Smart Wallet에서는 원본 secret을 되찾는 방식보다 승인 증거로 owner state를 변경하는 방식이 더 자연스럽습니다.

Candidate Primitives

Shamir와 LTSSS는 둘 다 유지하되, 역할을 다르게 둡니다

항목Shamir Secret SharingLTSSS
연구 내 역할표준적 기준선PQC 친화적 후보
강점검증성, 구현성, 설명 용이성lattice 기반 구조와의 정합성
한계단독 적용 시 차별성 약함표준화·파라미터·구현성 검증 필요
Smart Wallet 적합성둘 다 secret reconstruction 기반이므로 owner rotation 모델로 변환 필요

핵심 비교 기준은 “어떤 방식이 더 새롭나”가 아니라 owner key rotation에 필요한 threshold evidence를 어떻게 만들 수 있나입니다.
